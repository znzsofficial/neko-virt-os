# Product

## Register

product

## Users

NekoVirtOS is for users who want a usable browser-based virtual desktop system. The first version is desktop-only and focuses on people who will actively work inside the interface: opening apps, editing text files, managing local virtual files, and using a small set of built-in tools.

## Product Purpose

NekoVirtOS provides a polished web virtual operating system with real local utility. Success means the interface feels like a coherent desktop environment rather than a demo: windows can be managed reliably, files can be created and edited locally, and built-in apps feel consistent enough to support repeated use.

## Brand Personality

Cute, precise, quiet. The system should carry a Neko identity through small, deliberate details without letting decoration overpower the tool. It should feel calm, careful, and trustworthy while still having a distinct personal signature.

## Anti-references

NekoVirtOS should not look like a generic SaaS dashboard, a low-fidelity retro toy OS, or an overly anime-themed interface where characters and decoration dominate the workflow. Avoid template-like marketing sections, cheap glassmorphism, excessive visual noise, and novelty controls that make standard desktop tasks harder.

## Design Principles

1. Utility first, personality second: every cute detail must support orientation, feedback, or memory.
2. Desktop behaviors must feel dependable: window focus, resizing, file actions, and app state should be predictable.
3. Quiet surfaces, precise accents: the system should feel calm enough for long sessions while retaining a recognizable Neko signature.
4. Consistency over spectacle: built-in apps should share interaction patterns, density, focus states, and command vocabulary.
5. Local-first trust: make saved state, file persistence, and reversible actions visible enough that users trust the system.

## Accessibility & Inclusion

The first version is visually led, but it should not sacrifice basic usability. Maintain readable contrast for core text, visible focus states for primary controls, and reduced-motion alternatives for window and menu transitions. Full WCAG AA hardening can follow after the MVP interaction model is stable.
